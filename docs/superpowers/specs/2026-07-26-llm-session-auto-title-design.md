# LLM session auto-title

**Date:** 2026-07-26  
**Status:** accepted

## Problem

Sessions stay labeled `"New conversation"` / `"New swarm chat"` until renamed. Truncating the first user message is fast but often ugly or too literal. Users want ChatGPT-style titles generated by the configured LLM.

## Decision

**Placeholder from first user message, then LLM title after the first assistant reply.**

1. On first user message (while title is still a default placeholder): set a **provisional** title via existing `derive_session_title` (cleaned truncate). Emit SSE `session` with that title so the UI updates immediately.
2. After the first successful assistant `final` for that session: call the settings-backed LLM once to produce a short title; persist; emit SSE `session` again so the UI upgrades.
3. Only once per session: skip LLM retitle if the current title is no longer a default **and** we already ran LLM rename (or: only run when title was set as provisional / still matches derived first-message title). Simpler rule: **run LLM title only when the session still has never been LLM-titled**, tracked by a cheap signal.

### Title-state rule (simple)

- Defaults: `"New conversation"`, `"New swarm chat"`.
- First user append → provisional derived title (as today).
- After first `final` on a session whose title was auto-set (provisional) and that has exactly one user + one final (or: message_count indicates first completed turn) → LLM rename.
- Never overwrite a title the user set manually later (out of scope for v1 — no rename UI yet, so all auto titles are fair game until we add manual edit).
- v1 practical rule: **LLM title runs at most once**, on the first turn that produces a `final`, if the session title is still the provisional derived title from the first user message (or still a default if provisional somehow failed).

## Approaches considered

| Approach | Pros | Cons |
|---|---|---|
| A. LLM on first user message only | Fast path, one less wait after reply | Weak context; delays first token of the real turn if awaited |
| B. LLM after first reply only | Better titles | Sidebar stays `"New conversation"` during the whole first turn |
| **C. Placeholder then LLM (chosen)** | Instant UI + better final name | Two SSE updates; one extra LLM call |

## Behavior

### Prompt

Small, non-tool completion using `get_llm().complete()`:

- System: ask for a concise chat title (3–6 words), no quotes, no trailing punctuation, plain text only.
- User payload: first user message + first assistant final (truncate each to ~500 chars).

### Sanitize

- Strip quotes/markdown/newlines; collapse whitespace; max ~60 chars (reuse / share `derive_session_title` cleanup or a sibling sanitizer).
- Empty / garbage → keep provisional title; do not emit a second `session` event.

### Failure

- LLM misconfigured / request error / timeout: keep provisional title; log/debug; do not fail the chat turn.
- Title generation must **not** block streaming of the agent reply: run **after** the turn’s `final` is persisted and streamed (or as a fire-and-await after the agent loop for that turn, before trailing busy-false). Prefer: after loop completes for the first turn, await title call, emit `session`, then busy-false — so the reply is fully visible first; title may update a second later. Alternative: spawn title after `final` mid-stream without delaying deltas. **Chosen:** after agent loop finishes (all deltas/done already yielded), if eligible, await title, yield `session`, then yield busy-false.

### SSE / UI

- Existing `session` event `{ session_id, title }` — no new event type.
- UI already listens (`tomo:session-title`); works for provisional + LLM upgrade.

### Tests

- Unit: sanitize + eligibility helpers.
- Integration with `MockLLMClient`: first turn emits provisional `session`, then after final a second `session` with mock title; second turn emits none.
- Failure path: mock raises → provisional kept, turn still succeeds.

## Out of scope

- Manual rename UI
- Per-model title settings / cheaper title model
- Retitling after later turns
- Non-web channels

## Files (expected)

- `app/runtime/session_title.py` (or similar) — prompt + generate + sanitize
- `app/models/mixins/messages.py` / sessions — keep provisional rename; maybe `set_session_title`
- `app/channels/web.py` — call generator after first-turn loop
